## 0:25–0:55｜流程與資料粒度

> 「流程是 Python 匯入與檢查、SQLite 保存、SQL 日週分析，再匯出 Excel，供 Power BI 手動建置。我把生產與缺陷分成不同事實粒度：一組生產紀錄可能有多種缺陷，所以不直接連兩個事實表加總投入。」
>
> 「W41 有 590 投入、8 片不良板，但有 10 次缺陷，總不良率約 1.36%。缺陷次數不能當成不良板數。」

畫面：五張 KPI 或手算表。先說計數再說率，避免只報百分比。

## 0:55–1:30｜從總覽下鑽

> 「把範圍縮到 L1，投入 250、不良板 4、缺陷 5，有兩個生產組合，不良率是 1.60%。再縮到早班，投入 100、不良板 3、缺陷 4，只剩一組，不良率 3.00%。每次率都是目前分子與分母加總後相除，不是平均日率。」

畫面：依序選 L1、早班；或展示 Excel 相同彙總。Power BI 未驗證時：

> 「這是預定的切片與下鑽驗收數字；Power BI 互動尚未實測，所以我以 SQL／Excel 結果與建置規格示範，不宣稱互動已通過。」

「四組／兩組／一組」是生產組合數，不是優先清單命中數。

## 1:30–2:00｜週優先排序

> 「優先條件在 SQL 固定：週率至少為同週基準的兩倍，週投入至少 100，週不良板至少 3，並保留規則版本。判斷用未四捨五入的值，Power BI 只顯示結果，不因切片後基準改變而重新分類。」
>
> 「清單是調查優先順序，不表示已證明根因；還要核對產品組合、設備、材料批次與作業紀錄。」

畫面：週優先清單或 SQL 輸出；只指認實際命中列，不用手算的組合數冒充命中數。分類讀 `priority` 的優先、觀察、未觸發文字；基準固定為同週全部組合的總不良板／總投入。尚未操作驗證時明示為實作規格。

## 2:00–2:30｜缺陷與柏拉圖

> 「接著看缺陷次數的柏拉圖。分母是目前週、產線、班別、產品範圍內的缺陷次數；同次數的缺陷按代碼固定排序，累計最後到 100%。」

## 常見追問

| 問題 | 回答重點 |
|---|---|
| 為何不用 Excel 直接算？ | Excel 易閱讀；Python／SQLite 提供可重建、唯一鍵、檢查與版本追溯 |
| 為何缺陷 10 次但不良板只有 8？ | 同一板可有多缺陷，分析粒度不同 |
| 3% 一定異常嗎？ | 不是；需滿足週規則與樣本門檻，並考量產品組合與週完整度 |
| 為何不平均每天的不良率？ | 投入不同；先加總不良與投入再相除才是加權整體率 |
| 為何不讓缺陷圖篩所有 KPI？ | 缺陷維度只屬缺陷事實，不應改生產投入母體 |
| 同次數柏拉圖如何排序？ | 次數降冪、缺陷代碼升冪，累計與視覺使用同一穩定序 |
| 修正版會重複計算嗎？ | 依實作與實測紀錄回答；未完成驗證時明示待驗證 |
| 可以換電腦嗎？ | 設計為可重建；不複製 `venv6`，換路徑刷新，跨機結果尚待驗證 |
| 有改善成果嗎？ | 此為合成情境，不能宣稱實際良率提升或成本節省 |
