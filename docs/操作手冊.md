## 3. 模式、目錄與操作順序

每個模式使用獨立的 `data/<mode>/`：

| 路徑 | 用途 |
|---|---|
| `raw/` | 原始合成品質日報 |
| `archive/` | SHA 驗證來源封存、匯入鎖及交易前 SQLite 備份 |
| `revisions/` | 修正版輸入，例如 `品質日報_2026-10-05_v2.xlsx` |
| `quality.sqlite3` | 該模式的 SQLite 資料庫 |
| `output/品質分析.xlsx` | 分析、模型資料與週優先結果 |
| `output/檢查報告.xlsx` | 檢查結果與追溯線索 |

`case` 用於固定案例與手算；`demo` 用於展示資料量與互動。不得把兩種模式匯進同一份資料庫或在 Power BI 混用。

### 3.1 直接跑已附資料與另行生成

**開箱：儲存庫已附 raw 日報，首次只 run，不先 generate。** 生成器禁止覆蓋已存在日報，不刪除交付資料繞過保護。

```powershell
.\venv6\Scripts\python.exe -m quality run --mode case
```

**要生成新資料：** 在獨立工作副本備份設定後，將 `config/settings.json` 的 `modes.case` 改為 `data/new_case`、`modes.demo` 改為 `data/new_demo`，確認新資料夾無日報，再執行：

```powershell
.\venv6\Scripts\python.exe -m quality generate --mode case
.\venv6\Scripts\python.exe -m quality run --mode case
```

生成器不覆寫既有日報；若報已存在，另選新模式路徑，不刪原檔。執行後確認：

1. 命令沒有錯誤結束，使用的模式正確。
2. `quality.sqlite3`、兩份輸出檔存在且時間符合本次作業。
3. 檢查報告沒有未處理的重大錯誤。
4. W41 手算數字一致，不能僅以「檔案存在」判定成功。

### 3.2 修正版匯入與重新匯出

先確認修正版與原版具有相同業務日期、合理的版本識別與完整內容；不要只因檔名有 `v2` 就當作較新資料。原始交付 `case` 保留 v1，v2 僅在專案內獨立重建副本操作，先保留原版輸出，不覆寫交付基準。

```powershell
.\venv6\Scripts\python.exe -m quality import --mode case --file data/case/revisions/品質日報_2026-10-05_v2.xlsx --yes
.\venv6\Scripts\python.exe -m quality export --mode case
```

`--yes` 表示明確確認匯入，不應取代資料檢查或來源核對。匯入後的必要驗收：

- 原始版本仍可追溯，取代／保留策略清楚。
- 新版不是把原版相同業務鍵再加一份。
- 重匯相同檔案不重複增加數量。
- 無效修正版不能留下部分更新或破壞原有效資料。
- Excel 輸出與 SQL 查詢一致；若失敗，不刷新 Power BI、不打包不完整結果。

**上述為待驗收條件，不是已驗證的封存保證。** 目前建立的設計如下：

1. `archive/.import.lock` 排他鎖限制單一離線匯入者；異常殘留阻擋後續匯入。
2. 先複製來源至 `archive/.<token>.pending` 並驗證 SHA。
3. 使用 SQLite backup API 建立 `archive/.<token>.db.pending` 的交易前完整備份；不是直接複製開啟中的資料庫檔。
4. `BEGIN IMMEDIATE` 整日交易，替換該日有效投入與缺陷，更新 `import_batch`／有效日報指標，完成 commit。
5. 使用 `os.rename` 將來源暫存改名為正式封存。改名失敗時以 SQLite backup API 還原提交前狀態。

agent Linux 測試已涵蓋封存改名失敗的補償回復，以及回復也失敗時保留 pending／lock 並阻擋後續操作。此設計不是檔案系統與 SQLite 的分散式原子交易，錯誤注入測試不能保證跨系統強制斷電時同時完成。**強制斷電尚未驗證。**

發現鎖／pending 殘留時：

- 停止所有使用資料的程式，先備份整個 `data`，保留鎖、來源 pending、db.pending 與正式封存。
- 核對 `import_batch` 成功批次、有效日報及封存 SHA；不得只看檔案存在。
- 若沒有正式封存，以匹配的 `.db.pending` 經 SQLite backup API 回復；完整核對及命令見第 3.2.1 節，Windows 人工程序仍需實際驗證。
- 正式封存與成功批次相符、SHA 正確，或回復已確認後，才可清理對應暫存與殘留鎖。
- **不得直接刪除備份或移除鎖後硬匯入。** 不確定 token／狀態時維持阻擋，保留資料供檢查。

### 3.2.1 人工恢復：完整 PowerShell 與 SQLite backup 指令

**僅限單一離線寫入者。** 先停止所有 quality、Python、SQLite、Excel／Power BI 相關作業；確認沒有其他人或排程使用同一資料目錄。以下 Windows 指令尚未實測，強制斷電恢復也未驗證。不能在程式仍寫入時複製或恢復，不能以刪鎖代替停止程式。

在專案根目錄開 PowerShell，先備份**整個 data**到專案內新目錄：

```powershell
$ErrorActionPreference = 'Stop'
$Safety = Join-Path (Get-Location) ('recovery_backups\data_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
if (Test-Path -LiteralPath $Safety) { throw '備份目錄已存在，停止' }
New-Item -ItemType Directory -Path $Safety | Out-Null
Copy-Item -LiteralPath .\data -Destination $Safety -Recurse -Force
Get-ChildItem -LiteralPath $Safety -Recurse -Force
```

確認備份含兩模式、SQLite、正式封存、隱藏鎖及 pending，保存原狀。若 `modes` 在 `data` 外另有資料，亦須先備份該完整模式目錄。備份失敗不得繼續。

選定實際模式路徑，列出所有殘留。**不要使用「最新一個備份」或模糊萬用字元選 token**：

```powershell
$ModeFolder = 'data/case'
Get-ChildItem -LiteralPath "$ModeFolder/archive" -Force
$Token = Read-Host '輸入核對過的32位token（不含點號或副檔名）'
if ($Token -notmatch '^[0-9a-f]{32}$') { throw 'token 格式錯誤' }
```

以只讀方式核對來源 SHA、日報日期／版本、資料庫該 token 批次、交易前備份、預期正式封存有無。下列命令不恢復、不刪除：

```powershell
$Inspect = @'
import sys,sqlite3,hashlib,json
from pathlib import Path
from openpyxl import load_workbook
p=Path(sys.argv[1]); t=sys.argv[2]; a=p/'archive'
def ro(f):
    if not f.is_file(): raise SystemExit('缺少檔案：'+str(f))
    return sqlite3.connect(f.resolve().as_uri()+'?mode=ro',uri=True)
for f in sorted(a.glob('*.pending')): print('殘留',f.name)
for f in [p/'quality.sqlite3',a/('.'+t+'.db.pending')]:
    if not f.exists(): print('缺少',f); continue
    c=ro(f); c.row_factory=sqlite3.Row
    print('資料庫',f,'完整性',c.execute('PRAGMA integrity_check').fetchall(),'外鍵',c.execute('PRAGMA foreign_key_check').fetchall())
    print('目標批次',json.dumps([dict(r) for r in c.execute('SELECT * FROM import_batch WHERE batch_id=?',(t,))],ensure_ascii=False))
    print('有效日報',c.execute('SELECT report_date,batch_id FROM active_daily_report ORDER BY report_date').fetchall())
    c.close()
s=a/('.'+t+'.pending')
if s.exists():
    h=hashlib.sha256(s.read_bytes()).hexdigest()
    w=load_workbook(s.open('rb'),read_only=True,data_only=False)
    rows=w['日報資訊'].iter_rows(values_only=True); keys=next(rows); m=dict(zip(keys,next(rows))); w.close()
    print('來源SHA',h,'日報資訊',m)
    f=a/('品質日報_'+str(m['report_date'])+'_v'+str(m['revision_no'])+'_'+h+'.xlsx')
    print('預期正式封存',f,'存在',f.exists())
c=ro(p/'quality.sqlite3'); c.row_factory=sqlite3.Row
r=c.execute('SELECT * FROM import_batch WHERE batch_id=?',(t,)).fetchone()
if r:
    f=a/r['archive_path']
    print('批次指定封存',f,'存在',f.exists(),'SHA',hashlib.sha256(f.read_bytes()).hexdigest() if f.exists() else None)
c.close()
'@
.\venv6\Scripts\python.exe -c $Inspect $ModeFolder $Token
if ($LASTEXITCODE -ne 0) { throw '核對失敗，不得恢復或清理' }
```

核對 **token＝batch_id＝兩個 pending 檔名的 token**、SHA、日期及版本。`.db.pending` 應是此次 token 出現前的快照，不含該 token 成功批次；核對其有效日報為欲回復的舊版。、日期／版本矛盾、SHA 不符、備份錯誤或正式封存不明時，保留所有檔案與鎖，停止處理，**不能猜選備份**。

**分支 A：沒有正式封存，使用同 token 的 db.pending 回復。** 只有上述核對已確認屬同一次交易才執行；命令再檢查條件並以 SQLite backup API 恢復。成功後驗證完整性、外鍵、批次與有效日報，才清理該 token 暫存及鎖。完整 data 安全副本不刪除。

```powershell
$Restore = @'
import sys,sqlite3,hashlib
from pathlib import Path
from openpyxl import load_workbook
p=Path(sys.argv[1]); t=sys.argv[2]; a=p/'archive'
s=a/('.'+t+'.pending'); b=a/('.'+t+'.db.pending'); lock=a/'.import.lock'
assert s.is_file() and b.is_file() and lock.is_file(),'缺少來源、備份或鎖'
assert {f.name for f in a.glob('*.pending')}=={s.name,b.name},'其他token殘留，停止'
h=hashlib.sha256(s.read_bytes()).hexdigest()
w=load_workbook(s.open('rb'),read_only=True,data_only=False)
rows=w['日報資訊'].iter_rows(values_only=True); m=dict(zip(next(rows),next(rows))); w.close()
day=str(m['report_date']); rev=int(m['revision_no'])
name='品質日報_'+day+'_v'+str(rev)+'_'+h+'.xlsx'
assert not (a/name).exists(),'已有正式封存，不可走回復分支'
src=sqlite3.connect(b.resolve().as_uri()+'?mode=ro',uri=True)
assert src.execute('PRAGMA integrity_check').fetchall()==[('ok',)]
assert src.execute('PRAGMA foreign_key_check').fetchall()==[]
assert src.execute('SELECT 1 FROM import_batch WHERE batch_id=?',(t,)).fetchone() is None,'備份不是交易前狀態'
dbfile=p/'quality.sqlite3'; assert dbfile.is_file(),'現行資料庫缺失，停止'
dst=sqlite3.connect(dbfile)
r=dst.execute('SELECT report_date,revision_no,sha256,archive_path FROM import_batch WHERE batch_id=?',(t,)).fetchone()
assert r is None or r==(day,rev,h,name),'批次與來源不符'
assert not dst.execute('SELECT 1 FROM import_batch WHERE report_date=? AND batch_id<>? AND revision_no>=?',(day,t,rev)).fetchone(),'存在較新或衝突批次'
src.backup(dst)
assert dst.execute('PRAGMA integrity_check').fetchall()==[('ok',)]
assert dst.execute('PRAGMA foreign_key_check').fetchall()==[]
for table in ['import_batch','active_daily_report','production_input','defect_record','defect_code']:
    assert sorted(dst.execute('SELECT * FROM '+table).fetchall())==sorted(src.execute('SELECT * FROM '+table).fetchall()),'恢復後資料不一致'
dst.close(); src.close()
s.unlink(); b.unlink(); lock.unlink()
print('已由同token備份回復並驗證，清理該token暫存與鎖；保留整個data安全副本')
'@
.\venv6\Scripts\python.exe -c $Restore $ModeFolder $Token
if ($LASTEXITCODE -ne 0) { throw '恢復未完成；保留殘留與安全副本，禁止繼續匯入' }
```

**分支 B：正式封存存在且匹配成功批次。** 不回復舊快照；先核對批次、SHA、日期／版本、有效日報與資料庫完整性，成功才清該 token pending／鎖：

```powershell
$Finalize = @'
import sys,sqlite3,hashlib
from pathlib import Path
from openpyxl import load_workbook
p=Path(sys.argv[1]); t=sys.argv[2]; a=p/'archive'
s=a/('.'+t+'.pending'); b=a/('.'+t+'.db.pending'); lock=a/'.import.lock'
assert lock.is_file(),'無殘留鎖，停止'
assert {f.name for f in a.glob('*.pending')}.issubset({s.name,b.name}),'其他token殘留，停止'
fdb=p/'quality.sqlite3'; assert fdb.is_file()
c=sqlite3.connect(fdb.resolve().as_uri()+'?mode=ro',uri=True)
r=c.execute('SELECT report_date,revision_no,sha256,archive_path FROM import_batch WHERE batch_id=?',(t,)).fetchone()
assert r is not None,'無成功批次，不可清理'
day,rev,h,name=r
assert name=='品質日報_'+day+'_v'+str(rev)+'_'+h+'.xlsx','封存命名不符'
f=a/name; assert f.is_file() and hashlib.sha256(f.read_bytes()).hexdigest()==h,'正式封存缺失或SHA不符'
w=load_workbook(f,read_only=True,data_only=False)
rows=w['日報資訊'].iter_rows(values_only=True); m=dict(zip(next(rows),next(rows))); w.close()
assert str(m['report_date'])==day and int(m['revision_no'])==rev,'封存日期或版本不符'
assert c.execute('SELECT batch_id FROM active_daily_report WHERE report_date=?',(day,)).fetchone()==(t,),'有效版本非目標token'
assert c.execute('PRAGMA integrity_check').fetchall()==[('ok',)]
assert c.execute('PRAGMA foreign_key_check').fetchall()==[]
assert not s.exists() or hashlib.sha256(s.read_bytes()).hexdigest()==h,'來源pending與封存SHA不符'
c.close()
s.unlink(missing_ok=True); b.unlink(missing_ok=True); lock.unlink()
print('正式封存與成功批次一致，已清理該token暫存及鎖；保留整個data安全副本')
'@
.\venv6\Scripts\python.exe -c $Finalize $ModeFolder $Token
if ($LASTEXITCODE -ne 0) { throw '核對或清理未完成，禁止繼續匯入' }
```

若只剩鎖而無法由 token、來源或批次辨識其歸屬，不套用任一分支、不直接刪鎖。恢復後重新 export、核對 SQL／Excel，再刷新 Power BI；不要立刻 run 舊 raw 來掩蓋回復結果。上述人工 PowerShell 指令未實測，不將自動補償測試通過當作人工回復驗證。

## 4. 設定與規則

`config/settings.json` 控制模式根目錄、分析規則與 `rule_version`。目前鍵為 `modes`、`rate_multiplier`、`min_input`、`min_bad`、`rule_version`、`seed`、`defect_codes`；子目錄與輸出檔名依程式固定配置，不宣稱每條路徑均可單獨設定。

| 設定意義 | 預定值／原則 |
|---|---|
| `modes` | `{"case":"data/case","demo":"data/demo"}`；各模式隔離 |
| `rate_multiplier` | 2 倍，含等於門檻 |
| `min_input` | 100，含等於門檻 |
| `min_bad` | 3，含等於門檻 |
| 規則版本 | `rule_version`；規則變動時更新並保留來源 |
| 日期 | ISO `YYYY-MM-DD`；週為 ISO 週年＋週次 |

`seed` 為 20261005；`defect_codes` 定義 SHORT／短路／焊接、INSUF／錫少／焊接、SHIFT／偏移／組裝、MISSING／漏件／組裝。`rule_version` 目前為 `2026.1`。

週條件由 SQL 固定產出，使用未四捨五入的週率及同週全部組合總不良板／總投入基準。零基準倍數為空白、分類未觸發；不填無限大。達倍數且樣本足夠為「優先調查」，達倍數但樣本不足為「觀察（樣本不足）」，其餘為「未觸發規則」，未觸發不等於合格。規則變更後重新分析、匯出、刷新、驗收；不可只改 Power BI 卡片或 Excel 格式。

## 5. 資料粒度與檢查

以下為目前分析輸出契約，完整欄位見 Power BI 建置規格：

| 表 | 粒度 |
|---|---|
| `dim_date` | 一日期一列，含 `prod_date` 與 `week_key` |
| `dim_week` | 一 ISO 週一列，含唯一 `week_key`、`week_start`、`week_end` |
| `dim_line` | 一產線一列 |
| `dim_shift` | 一班別一列 |
| `dim_product` | 一產品一列 |
| `dim_defect` | 一缺陷代碼一列 |
| `fact_production` | 日期／產線／班別／產品一列，投入與不良板 |
| `fact_defect` | 一缺陷事件一列，含板序號／位置／檢驗站及來源，次數用列數 |
| `weekly_priority` | ISO 週／產線／班別／產品一列，SQL 週彙總與三類規則結果 |
| `說明` | `項目/內容`，含合成資料、UTC 匯出時間與資料截止日 |

業務鍵必須唯一；維度鍵不能空白；事實的鍵應存在於維度。檢查至少涵蓋：

- 日期能解析且格式為 ISO；不能把 ISO 週錯當日曆年週次。
- 計數是非負整數；不良板數不超過投入。
- 同一業務鍵的重複、空值及未受設定允許的缺陷碼。
- 缺陷總數與不良板數的合理對照：可大於，但不能把兩者當成同一指標。
- 檔案工作表／欄位不符、讀取失敗、版本衝突。
- 檢查報告能追到來源檔、工作表及列；不在輸出中只留模糊的「失敗」。

目前只有缺陷代碼受 `defect_codes` 控制，產線與產品不是受控清單，不宣稱會阻擋「未知產線／產品」。Linux 檢查與匯出已在 49 項測試／CLI 驗證；`檢查結果` 欄為「來源工作表、Excel列號、錯誤欄位、原因、處理摘要、是否阻擋」，另有「說明」工作表。Excel 桌面及 Power BI 的型別／呈現／互動仍未驗證，人工恢復與強制斷電也未驗證。

已回報測試亦涵蓋 Excel 文字公式防護；這不等於已在 Excel 桌面或 Power BI 驗證所有呈現與匯入行為。

## 6. SQL 日／週／缺陷分析

SQLite 實際使用 `production_input`、`defect_record`、`defect_code` 等表；Excel 的 `fact_production` 等不是資料庫表。下列日／缺陷範例可用既有 SQLite 工具查詢，週規則以程式載入的 `sql/weekly_summary.sql` 為唯一來源。該 SQL 使用程式註冊的 `iso_week()`，外部 SQLite 工具若未註冊不能直接執行，且需綁定設定參數。不另用工具的週次算法取代。

### 6.1 日品質

```sql
WITH defects AS (
    SELECT prod_date,line,shift,product,
        COUNT(DISTINCT board_sn) AS bad_boards
    FROM defect_record
    GROUP BY prod_date,line,shift,product
)
SELECT p.prod_date,
    SUM(p.input_boards) AS input_boards,
    SUM(COALESCE(d.bad_boards,0)) AS bad_boards,
    1.0 * SUM(COALESCE(d.bad_boards,0))
        / NULLIF(SUM(p.input_boards),0) AS bad_rate
FROM production_input p
LEFT JOIN defects d USING(prod_date,line,shift,product)
GROUP BY p.prod_date
ORDER BY p.prod_date;
```

率是小數，`0.016` 顯示為 `1.60%`；只在報表格式化，不在判斷前四捨五入。

### 6.2 週、產線、班別、產品

```sql
WITH d AS (
    SELECT prod_date,line,shift,product,
        COUNT(DISTINCT board_sn) bad_boards, COUNT(*) defect_count
    FROM defect_record GROUP BY prod_date,line,shift,product
), g AS (
    SELECT iso_week(p.prod_date) week_key,p.line,p.shift,p.product,
        SUM(p.input_boards) input_boards,
        SUM(COALESCE(d.bad_boards,0)) bad_boards,
        SUM(COALESCE(d.defect_count,0)) defect_count
    FROM production_input p
    LEFT JOIN d USING(prod_date,line,shift,product)
    GROUP BY iso_week(p.prod_date),p.line,p.shift,p.product
), rates AS (
    SELECT *,1.0*bad_boards/input_boards bad_rate,
        1.0*SUM(bad_boards) OVER(PARTITION BY week_key)
            /SUM(input_boards) OVER(PARTITION BY week_key) baseline_rate
    FROM g
)
SELECT *,bad_rate/NULLIF(baseline_rate,0) rate_multiple,
    CASE WHEN input_boards>=:min_input AND bad_boards>=:min_bad
        THEN '樣本足夠' ELSE '樣本不足' END sample_status,
    CASE WHEN baseline_rate=0 OR bad_rate<baseline_rate*:rate_multiplier
        THEN '未觸發規則'
        WHEN input_boards>=:min_input AND bad_boards>=:min_bad
        THEN '優先調查' ELSE '觀察（樣本不足）' END priority
FROM rates ORDER BY week_key,line,shift,product;
```

程式以設定綁定 `min_input=100`、`min_bad=3`、`rate_multiplier=2`。Python 匯出層再加入主要缺陷、理由、版本與暫定狀態成為 Excel `weekly_priority`。不得對整週基準先套 L1 篩選，亦不得以四捨五入值判定。

### 6.3 缺陷排行

```sql
SELECT d.defect_code,c.defect_name,COUNT(*) AS defect_count
FROM defect_record d JOIN defect_code c USING(defect_code)
WHERE d.prod_date BETWEEN '2026-10-05' AND '2026-10-11'
GROUP BY d.defect_code,c.defect_name
ORDER BY defect_count DESC,d.defect_code ASC;
```

缺陷排行計算事件列數；日／週查詢先將缺陷彙總到生產粒度再連接，不得把投入與原始缺陷逐列相連加總，否則投入放大。Power BI 仍禁止事實彼此關聯。

## 7. 手算驗收

將 `case` 切至 `2026-W41`，且沒有額外日期、產品、缺陷篩選：

班別欄 `shift` 實際值為「早／晚」；下列「早班」指 `shift = '早'`。

1. 全部：投入 **590**、不良板 **8**、缺陷次數 **10**、生產組合 **4**；率 `8/590` 約 **1.36%**。
2. 產線 L1：投入 **250**、不良板 **4**、缺陷次數 **5**、組合 **2**；率 **1.60%**。
3. L1＋早班：投入 **100**、不良板 **3**、缺陷次數 **4**、組合 **1**；率 **3.00%**。
4. 點選缺陷後，前三個生產品質 KPI 不變；缺陷圖可改變。
5. 優先清單的率、基準與結果跟 SQL 一致；上述組合數不是命中數。

修正版 v2 在獨立副本驗收：全週 **610／8／10／4**、約 **1.31%**；L1 **270／4／5／2**、約 **1.48%**；L1 早班 **120／3／4／1**、**2.50%**，小於未四捨五入的 `2×8/610`（約 **2.62295%**），為「未觸發規則」。L2 早班為「觀察（樣本不足）」。v1 缺陷 SHORT 4、INSUF 3、SHIFT 2、MISSING 1；v2 為 SHORT 3、INSUF 3、SHIFT 2、MISSING 2，v2 P1 SHORT 2／4＝50%。總數相同但分布不同，不是只有分母修正，也不是改善成效；文件代理未另行執行驗證。

日期或產品若另有篩選，分母不同，不能仍用原答案驗收。

## 8. 常見問題

| 現象 | 處理 |
|---|---|
| 找不到 `quality` | 確認在專案根目錄且使用專案環境 Python；核對原始碼是否完整 |
| 找不到檔案 | 核對 `--mode`、相對路徑、`config/settings.json` 與中文字檔名 |
| Excel 輸出被占用 | 關閉 Excel／Power BI 的相關檔案再匯出；不要刪資料庫解決鎖定 |
| 修正版匯入失敗 | 讀檢查報告與錯誤訊息，保留來源，不用 `--yes` 硬繞過檢查 |
| Power BI 數字放大 | 檢查一對多唯一鍵、關聯方向與事實對事實誤連接 |
| 週切片器無法篩到週表 | 確認使用 `dim_week[week_key]`，不是 `dim_date` 的週欄位 |
| 複製筆電後來源失效 | 重新設定 `ProjectFolder`，手動刷新及重新驗收 |
| 匯出時間沒有更新 | 明示暫定文字；不要把刷新時間當成資料生成／匯出時間 |
