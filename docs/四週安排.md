# 四週安排

## 目標與前提

四週完成的是「可解釋、可重建、驗證透明」的電子組裝產線品質異常分析求職作品，不是假裝已上線的工廠系統。資料全為合成資料（Synthetic Data）。

本排程為規劃，不表示任何週已通過驗收。Windows／Power BI 尚未驗證，本文件交付不含 `.pbix`。每週驗收必須留下實際環境、命令、結果與限制；未執行就記「待驗證」。

目前進度：agent Linux 實測 `case`／`demo` 完整 CLI，`pip check` 無衝突。封存改名失敗補償、補償失敗阻擋與 Excel 文字公式防護有測試覆蓋；最新測試與打包結果見下段。下列每週清單仍需依對應證據逐項勾選，不整週概括為通過。

最新進度取代上次紀錄：49 項全通過（8.97 秒），新增整週空窗日曆週覆蓋；同檔 run 再次驗證不增量。資料庫完整性／外鍵及封存 SHA 通過，Linux ZIP 87 檔 CRC 與排除項目通過，87 檔逐一秘密掃描未發現秘密。打包與本次秘密掃描已完成，USB／Windows／Power BI／強制斷電／正式審查仍不能標完成。

## 第 1 週：資料契約與可手算案例

### 工作

- 明確定義日期／產線／班別／產品的生產粒度及增加缺陷碼後的缺陷粒度。
- 整理 English `snake_case` 欄位、唯一鍵、ISO 日期與 ISO 週年。
- 區分投入板數、不良板數、缺陷次數；說明一板多缺陷。
- 核對 `config/settings.json` 的路徑、2 倍／100 投入／3 不良板及 `rule_version`。
- 建立 `case`／`demo` 隔離目錄，產生可手算案例。
- 確認依賴版本與 Linux Python 3.12.3 x64 環境。

### 產出

資料契約、合成日報、設定說明、檢查規則及手算基準。文件已同步實作欄位與封存設計，執行驗證仍在驗證狀態列出，不以檢視實作代替測試。

### 每週驗收

- [ ] `case`、`demo` 的原始、封存、修正版、資料庫、輸出互不混用。
- [ ] ISO `2026-W41` 全部：590 投入／8 不良板／10 缺陷／4 生產組合。
- [ ] L1：250／4／5／2、1.60%；L1 早班：100／3／4／1、3.00%。
- [ ] 來源日期、數量、唯一鍵與維度對應檢查可追溯。
- [ ] 缺陷次數沒有當成不良板數；彙總率不是平均日率。

面試練習：用 30 秒解釋為何缺陷 10 次不等於不良 10 板。

## 第 2 週：匯入、追溯、SQL 與 Excel

### 工作

- 核對 `generate`、`run`、`import`、`export` 介面與實際副作用。
- 開箱已附 raw，直接 run；另生成須先將設定 `modes.case/demo` 改到新的無日報資料夾，生成器禁止覆蓋既存日報。
- 確認封存與修正版設計：原版保留、相同業務鍵更新、重匯不重複、失敗可回復。
- 使用 SQL 產生日／週／缺陷查詢，不用事實彼此連接加總投入。
- 週優先條件以未四捨五入值判斷，同週固定基準由 SQL 產出。
- 匯出 `品質分析.xlsx`、`檢查報告.xlsx`，固定工作表與型別契約。
- 核對已列出的 `weekly_priority` 全部欄位及優先／觀察／未觸發表示法，驗證建置規格與輸出一致。

### 產出

可追溯資料庫、兩份 Excel、SQL 週優先結果、修正版處理證據。封存設計已建立，但強制斷電仍未驗證；殘留 pending／鎖時先停止所有程式、備份整個 data、核對批次與 SHA，不直接刪備份。

### 每週驗收

- [ ] 日／週加總一致；SQL 與 Excel 的投入、不良板、缺陷一致。
- [ ] 2 倍／100／3 邊界包含等於，零基準／零投入有明確處理。
- [ ] 顯示率四捨五入不改 SQL 命中結果。
- [ ] 重匯相同來源不增量；修正版不加出第二份同業務鍵。
- [ ] 原交付保留 v1；副本 v2 為 610／8／10、L1 早班 120／3／4、2.5%，低於約 2.62295% 門檻而未觸發；L2 早班為觀察。
- [ ] 無效檔案不造成部分更新；報告能指出來源與原因。
- [ ] `rule_version` 可追到設定與輸出。

面試練習：用 45 秒說明規則是「調查排序」，不是因果判定或統計顯著性證明。

## 第 3 週：Windows 與 Power BI 手動重建

### 工作

- Windows 使用 `py -3.12 -m venv venv6`，所有操作呼叫 `.\venv6\Scripts\python.exe`；不改執行原則。
- 核對 Windows 套件安裝與僅 Windows 的 `colorama==0.4.6`。
- 手動建立 `ProjectFolder`、每表 M 查詢、真日期型別及一對多單向模型。
- 關閉自動日期／時間與自動偵測關聯，避免事實彼此、雙向與重複週路徑。
- 建立 KPI、SQL 週優先顯示量值、穩定並列柏拉圖與四頁視覺。
- 編輯互動，使缺陷不影響投入、不良板、率；設定 ISO 週單選與下鑽。

### 產出

手動建置與驗收紀錄；本文件交付仍不建立 `.pbix`。若此週無 Windows／Power BI 可用，明確標示未驗證，展示改用 Excel、SQL 與建置規格，不假裝互動實測。

### 每週驗收

- [ ] Windows 新環境可安裝鎖定依賴並執行核心介面。
- [ ] 真日期、一對多單向、維度唯一鍵、單一週篩選路徑都確認。
- [ ] 四頁 W41、L1、早班手算數字一致。
- [ ] 優先清單與 SQL 固定基準一致，不隨切片重算。
- [ ] 缺陷點選不改生產 KPI，柏拉圖分母隨目前篩選且並列穩定。
- [ ] 手動換 `ProjectFolder` 並刷新成功，匯出時點有來源。

面試練習：用 60 秒解釋模型為何沒有事實對事實或雙向關聯。

## 第 4 週：交付、重建與求職展示

### 工作

- 核對七份文件與實作一致，保留 Windows／Power BI／強制斷電等尚未執行的明確限制。
- 打包 `deliverables/作品交付.zip`，排除虛擬環境、快取、秘密與 `.pbix`。
- 將 ZIP 複製到 USB，再複製到另一台筆電本機磁碟。
- 重新建立 `venv6`、安裝鎖定依賴、分析／匯出，依指南換 Power BI 來源。
- 演練三分鐘展示與沒有 Power BI 的備援展示。
- 最後整理驗證狀態，不將未執行事項列成通過。

### 產出

交付 ZIP、重建紀錄、三分鐘展示與精簡履歷敘述。建議履歷描述：「以合成品質日報建置 Python／SQLite／Excel 分析流程，規劃單向維度模型與 SQL 週異常排序。」只有完成實測才能加入「Windows／Power BI 已驗證」。

### 每週驗收

- [ ] ZIP 內容完整，不包含 `venv6`、`.pbix` 或真實公司資料。
- [ ] 從筆電乾淨目錄重建，不依賴原電腦絕對路徑。
- [ ] `case` 手算重現，`demo` 不污染 `case`。
- [ ] 四頁視覺配置、互動、下鑽與換路徑有實際證據或明示未驗證。
- [ ] 三分鐘內說完問題、粒度、規則、結果、限制與後續調查。
- [ ] 驗證狀態、匯出時點、規則版本與交付內容一致。

## 時程不足時的優先順序

優先保留：資料與率正確 → 重匯可追溯 → SQL 規則一致 → 手算驗收 → 交付可重建 → Power BI 互動 → 視覺美化。

不要為了展示完整而刪除未驗證標示；沒有 Power BI 可用時，仍可用 Excel、SQL 與完整建置規格交付，但必須清楚說明互動報表尚未實測。
