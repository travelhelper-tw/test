## 1. 交付範圍

本作品為電子組裝產線品質異常分析的合成資料（Synthetic Data）求職作品。預定交付 `deliverables/作品交付.zip`，不建立、不交付 `.pbix`，不打包 `venv6`。

交付容器不代表跨機成功。Windows、Power BI Desktop、Excel 桌面與 Windows 專用套件尚未驗證；封存設計已建立，但強制斷電與跨系統回復未驗證。

已回報 Linux 最新 49 項 pytest 全通過（8.97 秒）、完整 CLI：`case` 2 日報 590／8／10；`demo` 28 日報 69,225／818／1,146、完整 4 週、72 週組合列。環境 Python 3.12.3 x64、SQLite 3.45.1，`pip check` 無衝突。新增整週空窗日曆週覆蓋測試；同檔 run 再次全跳過、數據與輸出不變。兩模式完整性／外鍵／封存 SHA 通過，**Linux 打包 87 檔、CRC 與排除項目已驗證**。強制斷電、秘密掃描、正式審查與跨機重建尚未驗證。

## 2. 應包含與排除

- 專案 Python 原始碼與核心命令入口。

- README 與六份指定 `docs/` 文件。
- `data/case/` 與 `data/demo/` 的合成輸入、修正版、必要追溯封存。
- 各模式的 `quality.sqlite3`、`output/品質分析.xlsx`、`output/檢查報告.xlsx`。
- 資料與匯出時點、實際驗證狀態的可追溯資訊；尚未串接則明示待驗證。

正式來源封存可交付；`archive/.import.lock` 或任何 pending 殘留時必須先停止打包並回復，不能把未完成交易當正常成果。既有 `voicebook-guide.md` 不屬本次文件交付，文件製作不讀取、不修改它；不能宣稱已檢查其內容。

### 不應包含

- `venv6` 或其他虛擬環境、套件安裝目錄。
- `.git`、`__pycache__`、測試快取與無用工作檔。
- `.pbix`。
- 憑證、權杖、密碼、私人設定、真實公司日報。
- 以前的 `作品交付.zip` 本身或整個 `deliverables/` 再包進新 ZIP。
- 不在本次作品範圍內且未經核對的檔案。

打包程式的實際排除清單需驗證，不以此文件當成已實作保證。

主代理已改允許清單並實測 ZIP 排除 venv、既有 `voicebook-guide.md` 及 pbix；文件代理不讀取既有指南。排除驗證不等於秘密掃描通過，後者仍待執行。

## 3. 打包前檢查

1. 確認所有資料都是合成資料，沒有真實公司名稱或來源紀錄混入。
2. 核對兩種模式互相隔離；資料庫與 Excel 屬同一次有效匯出。
3. 關閉 SQLite 寫入與 Excel 檔案，避免打包未完成或被占用的輸出。
4. 閱讀檢查報告；重大檢查未處理前不把資料標記為可展示。
5. 核對 `config/settings.json` 路徑與規則；不帶原電腦秘密或無法轉移的絕對路徑。
6. 核對 `rule_version` 與 SQL 週結果；Power BI 不另算條件。
7. 更新驗證狀態；未測 Windows／Power BI 仍標未驗證。
8. 檢查依賴鎖定與原始碼完整度。
9. 確認原始 `case` 保留 v1 手算基準，v2 演練副本不混入正式交付。
10. 有 pending／匯入鎖殘留時先停止所有程式、備份整個 data，核對 `import_batch` 與封存 SHA；未正式封存時以匹配 `.db.pending` 經 SQLite backup API 回復。正式封存與成功批次一致才清理對應暫存，**不得直接刪備份或解除鎖硬打包**。

## 4. 執行封裝與核對內容

於 Windows 專案根目錄：

```powershell
.\venv6\Scripts\python.exe -m quality package
```

輸出 `deliverables/作品交付.zip`。Linux 已執行：87 檔、`testzip()`＝`None`，CRC 通過；venv／既有指南／pbix 排除確認。ZIP 在被忽略的 `deliverables`，不提交，但可用命令重產；新增或修改文件後應重新打包，舊 ZIP 不會自動更新。跨機重建仍待驗證。每次重產後：

- 打開 ZIP 清單，逐項對照第 2 節。
- 確認內部路徑是專案相對路徑，不是原電腦磁碟絕對路徑。
- 確認兩種模式、原始碼、設定、依賴檔與七份文件齊全。
- 確認沒有 `venv6`、`.pbix`、秘密與遞迴 ZIP。
- 在專案子目錄建立獨立解壓副本做檢查；不要覆寫唯一工作副本。
- 如需傳送驗證，可計算 SHA-256；收件者比對的是完整性，不是分析正確性。

```powershell
Get-FileHash -Algorithm SHA256 .\deliverables\作品交付.zip
```

把實際雜湊與產出時間記入交付紀錄。文件不預填不存在的雜湊。

## 5. USB 與另一台筆電重建

### 5.1 複製

1. 將 `作品交付.zip` 複製到 USB。
2. 在另一台 Windows 筆電，先複製 ZIP 到本機磁碟，再解壓到可寫入目錄，例如 `C:\作品\品質分析`。
3. 不直接從 ZIP 執行，不依賴 USB 磁碟代號，不複製舊 `venv6`。
4. 若 USB 有完整性雜湊，先核對。
5. 確認 Python 3.12 x64 已安裝；Power BI Desktop／Excel 由該筆電自行安裝，本 ZIP 不提供安裝程式。

### 5.2 重新建立 Python 環境

在解壓後專案根目錄開 PowerShell：

```powershell
py -3.12 -m venv venv6
.\venv6\Scripts\python.exe --version
.\venv6\Scripts\python.exe -m pip install -r requirements.txt
.\venv6\Scripts\python.exe -m pip check
```

後續全部呼叫 `.\venv6\Scripts\python.exe`；不啟用 PowerShell 環境、不改執行原則。第一次安裝通常需要網路與可用的套件來源；**離線重建尚未驗證**。Linux 的套件安裝結果不能替代 Windows 專用 `colorama==0.4.6` 驗證。

### 5.3 核對現有輸出，再重建案例

**直接跑已附資料：** 先保留解壓的原輸出副本，閱讀檢查報告，首次只 run；已附 raw，生成器禁止覆蓋日報，不先 generate：

```powershell
.\venv6\Scripts\python.exe -m quality run --mode case
.\venv6\Scripts\python.exe -m quality export --mode case
```

展示模式已附資料同樣只需：

```powershell
.\venv6\Scripts\python.exe -m quality run --mode demo
```

**要生成新資料：** 在獨立工作副本將設定 `modes.case` 改為 `data/new_case`、`modes.demo` 改為 `data/new_demo`，保留其他設定，確認兩個新資料夾沒有既存日報再執行：

```powershell
.\venv6\Scripts\python.exe -m quality generate --mode case
.\venv6\Scripts\python.exe -m quality run --mode case
.\venv6\Scripts\python.exe -m quality generate --mode demo
.\venv6\Scripts\python.exe -m quality run --mode demo
```

不要刪除已附 raw 來解除生成器保護。模式路徑改後，v2 的 `--file` 改為對應新資料夾的 `revisions`；下列指令只適用保留原 `data/case` 設定的副本。

若需演練修正版，在另一份案例副本操作，避免改變基準展示狀態：

```powershell
.\venv6\Scripts\python.exe -m quality import --mode case --file data/case/revisions/品質日報_2026-10-05_v2.xlsx --yes
.\venv6\Scripts\python.exe -m quality export --mode case
```

確認重匯不重複、來源可追溯、檢查報告與 SQL 一致。副本 v2 應為全週 610／8／10、L1 270／4／5、L1 早班 120／3／4、2.5%，小於約 2.62295% 的兩倍整週基準，未觸發；L2 早班為觀察。不得拿 v2 與 v1 的投入／分類答案混用。封存有交易前 SQLite 備份，但跨系統不具分散式原子性，強制斷電未驗證。

本 ZIP 沒有 `.pbix`；依[建置規格](PowerBI建置規格.md)手動建立：

1. `ProjectFolder` 設為 `C:\作品\品質分析\data\case`。
2. 建立來源函數與每表 M 查詢，確認真正日期及數量型別。
3. 最新交付目標為 **10 張分析模型表＋「說明」＝11 張**；目前可核對的命名契約仍列 9 張分析表，第 10 張名稱／欄位待主實作同步，不能編造查詢或宣稱十一表驗收通過。以最終實際工作表清單核對，更新建置規格後全部關聯一對多單向，關閉自動日期／關聯。

7. 從「說明」讀 UTC 匯出時間及資料截止日；呈現尚未驗證時留「待驗證」，不能把本機刷新時間冒充資料匯出時間。
